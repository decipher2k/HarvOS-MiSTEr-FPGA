Boot-ROM und ELF-Loader

Das Boot-ROM erkennt zwei Blockdevices, mountet deren Dateisysteme, ordnet ELF, YAML und Datenordner zu, laedt gueltige ELF32-Images in IMEM/DMEM und uebergibt danach kontrolliert an die Anwendung.

Bootsequenz

  1. Reset: Das SoC initialisiert IMEM, DMEM und Geraete. Hart 0 startet bei 0x00000000.
  2. Secure Boot setzt boot_ok und mpu_lock, sofern Hash/Signaturwerte stimmen.
  3. Boot-ROM initialisiert den HPS-Block-Adapter bei 0xffff00c0.
  4. Beide Images werden als Blockdevices behandelt und per FAT/exFAT-Abstraktion gemountet.
  5. Das Programmlaufwerk wird anhand von *.elf im Root erkannt.
  6. Das Datenlaufwerk wird anhand des Verzeichnisses /data erkannt.
  7. Das Boot-ROM sucht die erste gueltige App: /name.elf, /config/name.yaml, /data/name.
  8. Die YAML-Datei wird geparst und in eine interne App-Konfiguration uebersetzt.
  9. ELF-Header und Program Header werden validiert.
  10. Ausfuehrbare Segmente werden via IMEM-Loader geschrieben; Datensegmente und BSS gehen in DMEM.
  11. Startparameter und optionales HarvTTP-Bundle werden in DMEM platziert.
  12. Der IMEM-Loader wird gelockt.
  13. Das Boot-ROM setzt a0 = params_addr, setzt sp und springt zum ELF-Entry.

Das HarvTTP-Webroot liegt im aktuellen Projekt absichtlich unter /confg/harvttp/httproot. Der Pfad ist so im Boot-ROM und in den Startparametern dokumentiert. Ein spaeterer ABI-Bruch sollte ihn auf /config/harvttp/httproot migrieren.

Ladeverhalten

PT_LOAD-Segmente mit PF_X werden als Code behandelt. Das Boot-ROM liest sie stueckweise aus dem Dateisystem, paddet auf Wortgrenzen und schreibt sie ueber die Register des IMEM-Loaders in den Instruktionsspeicher. Nicht-ausfuehrbare Segmente werden byteweise in DMEM kopiert. Wenn memsz > filesz, wird der Rest auf null gesetzt. 

for each PT_LOAD phdr:
  reject if phdr.flags has both PF_W and PF_X
  if phdr.flags has PF_X:
    write_exec_segment_via_imem_loader(phdr)
  else:
    copy_to_dmem(phdr.filesz)
    zero_bss(phdr.memsz - phdr.filesz)

Fehlerverhalten

Boot-Fehler werden ueber ein Debugwort bei 0x00000420 sichtbar gemacht. Statuswerte beginnen mit 0xB001....; Fehler werden als 0xBAD00000 | status kodiert. Im aktuellen Boot-ROM wird die erste gueltige App gestartet. Fuer einen echten Multi-App-Produktionspfad sollte ein Supervisor geladen werden, der mehrere ELF-Dateien isoliert und schedult.
