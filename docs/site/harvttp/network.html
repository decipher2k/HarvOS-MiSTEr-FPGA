Netzwerkpfad

HarvTTP spricht nicht ueber einen Host-Socket. Der Server arbeitet ueber die HNET-MMIO-Netzwerkkarte des HarvOS-SoC. Im Verilator-Testpfad werden die Ethernet-Frames zur Host-Seite ueber Npcap/TAP/Wintun-nahe Infrastruktur ausgeleitet.

HNET-Ablauf

  1. HarvTTP setzt HARVOS_NET_CTRL_ENABLE und konfiguriert IRQs.
  2. Die MAC-Adresse wird in MAC_LO/MAC_HI geschrieben.
  3. Empfang: Wenn RX_VALID gesetzt ist, startet HarvTTP RX_START.
  4. HNET schreibt den Frame ins DMA-Fenster; HarvTTP liest FRAME_LEN.
  5. Senden: HarvTTP kopiert einen Frame ins DMA-Fenster und startet TX_START.
  6. Der TX-Pump-Thread leert bei Bedarf die 64-Frame-Queue.

DHCP-Zustandsmaschine

state DISCOVER:
  send DHCPDISCOVER
  wait for OFFER with matching XID

state REQUEST:
  send DHCPREQUEST for offered IP
  wait for ACK with matching XID

state ACK:
  net.bound = true
  HTTP traffic on port 80 is accepted

Sobald der Server gebunden ist, protokolliert er die IP ueber den Audit/IPC-Pfad. In der aktuellen Testumgebung war die erreichbare Adresse zuletzt 192.168.8.231; die tatsaechliche IP ist aber Ergebnis des jeweiligen DHCP-Testnetzes.

TX-Optimierung

Die aktuelle Version nutzt ein hybrides Sendeverhalten: Wenn HNET TX_READY meldet und die Queue leer ist, sendet HarvTTP sofort. Andernfalls wird der Frame in eine 64-Slot-Queue kopiert und durch den TX-Thread abgearbeitet. Das reduziert Latenz bei niedriger Last und verhindert, dass kurze Antwortbursts sofort verloren gehen.

Browserzugriff

Der Browser muss die DHCP-IP des HarvOS-Servers erreichen. 127.0.0.1 ist nur dann korrekt, wenn ein expliziter Port-Forward oder Proxy eingerichtet wurde. Fuer den CPU-echten Pfad ist die IP aus dem HarvOS-Testnetz zu verwenden, beispielsweise http://192.168.8.231/.
